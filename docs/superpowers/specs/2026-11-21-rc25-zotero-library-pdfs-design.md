# rc25: Zotero library and PDFs (design)

Owner decisions 2026-11-21. Calls marked "(my call)" need review. Build on rc24's OAuth connection, source snapshots and citation picker, after rc23's dashboard removal. [rc24 design](2026-11-21-rc24-essays-mla-zotero-design.md) · [Zotero research and pdf-tui addendum](2026-11-21-zotero-client-research.md)

## Why

The owner keeps their PDFs in Zotero Storage. They want to read on the HP Stream, highlight a passage or add a note, and see those marks in Zotero the next time they open it. They also want to carry a quote and its page number into their writing. Library search and downloaded PDFs should work offline.

## Goals

1. Pull the personal library for offline browsing. Search by title, creator or year, and filter by collection and tag.
2. Download a stored PDF on request. Read its text with page labels and file page numbers beside the writing.
3. Show existing Zotero annotations. Create highlights, highlight comments and anchored notes. Save them offline and send them to Zotero with explicit write consent.
4. Take a quote to a project note or insert a quote and its citation at the saved writing cursor. Carry the locator from the PDF and let the writer correct it.

## Non-goals

- General Zotero edits, group libraries, saved searches, library note editing, annotation deletion, attachment upload and bulk PDF downloads. (my call)
- WebDAV, linked files on another device, publisher downloads and arbitrary web attachments.
- Page images, OCR, figure selection, ink and image annotation creation. Draw page images natively in a later release. (my call)
- A new dashboard, a fourth clearing carousel view or changes to other #163 project shapes.

## Anti-goals

- A library refresh that writes to Zotero or a PDF download that starts while browsing a list.
- A highlight that lands on the wrong passage after a file changes.
- Retrying an uncertain write as a second highlight, or losing an unsent comment on logout, update or conflict.
- The PDF, the account database or the key ending up in a project, its Drive mirror or its timeline.

## Approaches considered

- **Keep rc24 live search, or keep a local library.** Use a local SQLite database for collections, tags, items, attachments, annotations and the send queue. (my call) Versioned pulls and transactions make interrupted refresh and offline reading manageable. Use WrOS's own schema and the Web API. Zotero's desktop database stays under Zotero's control. [Zotero sync protocol](https://www.zotero.org/support/dev/web_api/v3/syncing) · [Zotero database guidance](https://www.zotero.org/support/dev/client_coding/direct_sqlite_database_access) · [SQLite WAL](https://www.sqlite.org/wal.html)
- **A separate terminal reader, page images, or text first.** Choose text first. (my call) Use Poppler word boxes so selecting visible words has a path back to the PDF. Use pdf-tui for ideas on navigation and copying. Its terminal image protocols target terminals such as Foot. The default WrOS DRM session draws its own cells. Later draw a page image through the native renderer and keep this release's document and position model. [pdf-tui](https://github.com/WindustH/pdf-tui) · [Poppler text tool](https://github.com/tsdgeos/poppler_mirror/blob/master/utils/pdftotext.1) · [WrOS display paths](../../GRAPHICAL_SESSION.md) · [DRM renderer](../../../crates/wros-graphics/src/kms.rs)
- **Put marks in the PDF, or send annotation items.** Use annotation items. (my call) Zotero syncs these as child items of the attachment and stores them outside the PDF. This gives the owner marks in Zotero's annotation list without a PDF upload. [Zotero annotation storage](https://www.zotero.org/support/kb/annotations_in_database) · [Zotero team on annotation reads](https://forums.zotero.org/discussion/105207/access-pdf-annotations-via-zotero-web-api) · [Server accepts annotation fields](https://github.com/zotero/dataserver/blob/master/model/Items.inc.php)
- **Turn on full library writes, or add annotation writes only.** Keep a read-only library workflow. Offer a separate step to authorize annotations. (my call) Zotero grants personal-library write access, which is broader than this feature. WrOS confines writes to supported annotation items on the connected personal library. [Zotero OAuth permissions](https://www.zotero.org/support/dev/web_api/v3/oauth) · [Write request rules](https://www.zotero.org/support/dev/web_api/v3/write_requests)

## Decided details

### The desk

Give the Zotero library two entry points. It opens a small overlay, with a **Read beside…** action for a downloaded PDF. Use the existing side space beside a document if it fits and the second editable pane is closed. If it doesn't fit, open the same reader in a compact overlay with one column. Keep the writing pane's cursor, selection and scroll. Keep `F11` for the editable second pane and keep the clearing carousel as it is. Close or suspend the reader when it would cover the writer's existing secondary editor. (my call) [Menu](../../../src/app/overlays/bar.rs) · [Palette](../../../src/palette.rs) · [Beside state](../../../src/app.rs) · [Pane layout](../../../src/ui.rs) · [Every key](../../../assets/help/24-every-key.md)

The Tools path starts in the overlay. The View path opens the library in the beside space when it fits, with the same fallback to the overlay. Within it, select a collection, tag, item or PDF. `Tab/Shift-Tab` move between filters, search, results and actions. `↑/↓` move in a list. `←/→` fold or unfold a collection when the tree has focus. `Enter` opens the selected item or activates an action. `Esc` goes back one step, then returns to the writing. Use the main menu's `Esc` or `F10` and the existing `Ctrl-K` palette. Add no global binding. Recheck the rc23 Tools rows and use its Notes side group. - In PDF text, `←/→` move by word and `↑/↓` move a line. `Shift` with those arrows extends a word selection. Mouse dragging can select the same words. `PgUp/PgDn` move a screenful. At a page boundary they continue to the next or previous PDF page. **Go to page…** accepts a file page or an unambiguous label. `Tab/Shift-Tab` move between text, annotations and actions. `Enter` opens the focused action. `Esc` clears a selection, then backs out of the reader. Keys apply in this reader only. Preserve `Ctrl-F` for the writing editor and `Ctrl-K` for the palette. Show a gutter marker as well as color. On a narrow screen use a single text column and a separate annotations list within the same box. (my call)
- **Backups and accounts › Zotero** keeps **Account**, **Access** and **Disconnect Zotero…**. Add **Sync library now**, **Last synced · <time>**, **Enable PDF annotations…** or **Disable PDF annotation sync…**, **Pending annotations…** and **Downloaded PDFs…**. The Pending annotations dialog shows drafts, failed sends and **Sync pending annotations**. The reader's **Pending…** opens the same dialog. Show cache usage and **Remove unpinned downloads…** inside Downloaded PDFs. Each attachment offers **Keep offline** or **Unpin**. A read-only user can download, read, quote and see annotations if the verified grant permits the reads. On an unwritable page, show why, keep text actions where they work, and offer **Enable PDF annotations…** when permission is the issue. ### Consent and the library pull

- Use rc24's credentials for the read-only library. Verify the separate file capability in `/keys/current` and a real download before calling the grant ready for PDFs. Ask for **Enable PDF annotations…** only when chosen. Reuse the QR and typed verifier for a new grant on the same account. Explain that Zotero gives WrOS personal-library write access and WrOS uses it for PDF annotations. Ask for personal library read and write, groups none and regular notes off. Current server source treats `itemType=note` as a separate read scope and attachments expose annotations as children. Verify that both annotation reads and file downloads work with those minimal grants. If Zotero requires additional access, stop the pairing and explain the actual requirement before requesting it. Preserve the old grant until the new one is verified. Reject a switched account and unwarranted grants. Use the rc24 revocation path for a grant no longer needed. To disable writes, return to a verified read-only grant or disconnect the write grant. Keep queued work local until the writer settles it. (my call) [OAuth permission defaults](https://www.zotero.org/support/dev/web_api/v3/oauth) · [Key capabilities](https://www.zotero.org/support/dev/web_api/v3/syncing#verify_key_access) · [Server access rules](https://github.com/zotero/dataserver/blob/master/model/Permissions.inc.php) · [Attachment children on the server](https://github.com/zotero/dataserver/blob/master/controllers/ItemsController.php)
- (my call) **Sync library now** pulls only. **Sync pending annotations** sends queued edits and runs the pulls needed to check and reconcile those writes. Opening the library is local. The library shows a last good snapshot, pending count and progress. It opens offline without waiting. Local search uses windowed results. An explicit sync runs one cancellable worker per account. It keeps the previous snapshot visible until it has a consistent new one. Stop early on missing privileges or account mismatch. Respect `Backoff`, `Retry-After`, auth failures and throttling. Repeated failures need a deliberate retry. [Zotero sync protocol](https://www.zotero.org/support/dev/web_api/v3/syncing) · [API backoff and status](https://www.zotero.org/support/dev/web_api/v3/basics)
- Start at `since=0`. Verify key access, pull collection, top-level item and all item version maps with `includeTrashed=1` for items, then request records in batches of at most 50 keys. Pull parents before child attachments and annotations. Skip saved searches and regular note content. Read tags and membership from the item data. Fetch `/deleted?since=…` and hide trashed or deleted objects and their children from normal search. Stage data and tombstones and promote them with the checkpoint in one transaction when the responses agree on `Last-Modified-Version`. On a mismatched version or interruption retain the old checkpoint and restart or safely discard the staged pass. Use `If-Modified-Since-Version` for the idle check. During a send, a `304` still leaves pending local work to send. A failed item batch never moves the visible checkpoint past it. [Zotero version, batch and deletion algorithm](https://www.zotero.org/support/dev/web_api/v3/syncing)
- **Copy source…** and **Insert citation here…** reuse rc24's source preview. Map cached Zotero bibliographic fields to CSL-JSON locally, so a source can be added while offline. Pin and test the mapping against the API's CSL-JSON for supported types. Keep project edits and stable keys if the library changes. If an item has no supported source mapping, show the manual source form. Keep the quoted text and the page value in the form. (my call) [Zotero schema and CSL mappings](https://github.com/zotero/zotero-schema) · [API item formats](https://www.zotero.org/support/dev/web_api/v3/basics)

### Downloads and page positions

- **Download PDF** uses the personal attachment's `GET /users/<id>/items/<attachmentKey>/file` route. Show progress and **Cancel download**. Follow a bounded HTTPS redirect from the authenticated API to the verified Zotero Storage delivery host. Strip API headers and cookies across hosts. Keep signed redirect URLs out of logs and disk. Validate PDF type, size and declared checksum where available. Store the response in a private partial file and promote it only after validation. For a Zotero-compressed stored PDF, read one expected PDF from a bounded archive into the same pipeline and verify its uncompressed bytes. Reject unsafe paths, mismatched contents, oversized archive members and unexpected formats. A missing remote file, lack of permission or unsupported link mode explains what happened in the attachment row. (my call) [Zotero desktop file route and headers](https://github.com/zotero/zotero/blob/9.0.6/chrome/content/zotero/xpcom/storage/zfs.js#L69-L119) · [Storage delivery source](https://github.com/zotero/dataserver/blob/master/model/Storage.inc.php) · [Zotero stored and linked files](https://www.zotero.org/support/attaching_files)
- Use `pdftotext -bbox-layout` with `-f` and `-l` for one page at a time. It extends `-bbox` with layout boxes. Use the same ordered word stream for display and selection. Keep block, line and word identity across wrapping. Parse XHTML as data. Use local PDF metadata for page count, boxes, rotation and PDF page labels. Display the rendered label and 1-based file ordinal separately. The annotation payload uses the 0-based file page index and the PDF user-space rectangles. Map Poppler's top-left output back through the same chosen page box and inverse page rotation. Account for non-zero box origins. Prove the transform against desktop-created rectangles, including a rotated and cropped page. Build a rect for each consecutive selected run on a line and keep separated columns apart. Restrict a new selection to one page and whole words. (my call) [Poppler flags](https://github.com/tsdgeos/poppler_mirror/blob/master/utils/pdftotext.1) · [Zotero reader position and selection](https://github.com/zotero/reader/blob/master/src/pdf/selection.js) · [PDF coordinate reference](https://mupdf.readthedocs.io/en/1.26.1/pdf/)
- Use a bounded, unprivileged local extractor with time, input and output limits. Extract on demand and prefetch at most one neighboring page from a downloaded file. Protect the editor from parser failures. If a page has no text layer, show its label and existing annotation list. If the text geometry is ambiguous or extraction fails, allow plain reading where possible and show why a new highlight or note can't be placed. Match imported highlight rectangles to words, using position first and checking text where available. Show an annotation in the list even when the boxes cannot be matched. Unknown types show the label, type and any plain text with no editable geometry. Strip terminal controls and render incoming markup as safe text. Never re-anchor an annotation by guessing based on similar text. (my call) [Poppler limitations](https://github.com/tsdgeos/poppler_mirror/blob/master/utils/pdftotext.1) · [Zotero reader guidance](https://www.zotero.org/support/pdf_reader)
- Cache by account, attachment key and file content hash. Remember the server storage hash or file revision and observed PDF geometry. A changed file invalidates that text cache. Allow rereading an older cached file offline with a stale mark. Queue each local annotation against the file it was made on. Before sending, confirm the parent and attachment still exist and that the server copy matches the stored file revision or checksum. If identity is unknown or changed, hold the edit and offer to keep its text or reselect on the fresh file. Keep the earlier pending text until the replacement is saved. Version the write against the checked library state so a sync race gets a retry. (my call) [Zotero file metadata headers](https://github.com/zotero/dataserver/blob/master/controllers/ItemsController.php) · [Zotero on changing PDF pages](https://www.zotero.org/support/pdf_reader) · [API version checks](https://www.zotero.org/support/dev/web_api/v3/syncing)

### Annotation writes and quotes

- **Highlight** uses the selected words and their rectangles. **Add highlight comment…** adds a plain-text comment to a new highlight or a writable highlight created by WrOS. **Add note…** anchors a sticky note to the focused word with a plain-text comment. (my call) Existing Zotero highlights and notes show their page, text, comment and color. They can be quoted. Keep them read-only in rc25 unless WrOS made the entry and recognizes its last synced version. Offer comment changes on those entries. Leave move, recolor, delete, images and ink for later. Keep note and highlight state after switching pages. [Zotero reader and notes](https://www.zotero.org/support/pdf_reader) · [Desktop serialization](https://github.com/zotero/zotero/blob/9.0.6/chrome/content/zotero/xpcom/data/item.js)
- Send an item with `itemType: annotation` with `parentItem` set to the attachment key. Use `annotationType` of `highlight` or `note`, `annotationText` only on highlights, `annotationComment`, `annotationColor`, `annotationPageLabel`, `annotationSortIndex` and a JSON string for `annotationPosition` with page index and rects. Start with one standard highlight color and one note color. Derive ordering from the reader's page, nearest character offset and top position convention. The offset from Poppler is a candidate. Check it against Zotero on multiparagraph and multicolumn pages before enabling writes. Do not use terminal row numbers as geometry or sort offsets. Prove that both records appear in Zotero desktop and on the owner's phone platform using a disposable library. [Server annotation fields and validation](https://github.com/zotero/dataserver/blob/master/model/Items.inc.php) · [Zotero reader position and sort index](https://github.com/zotero/reader/blob/master/src/pdf/selection.js)
- Write the pending record and send-queue entry in one SQLite transaction before the UI says **Saved on this laptop**. Give each creation a stable Zotero-format item key, allocated once. A send uses a conditional write and a version check. Use `POST /users/<id>/items` with the item key and version `0`, and `If-Unmodified-Since-Version` tied to the checked library version. Process per-item results. On success persist the server key and version before clearing the queue entry. For a timeout or lost reply, look up that same key. If it contains this exact annotation, acknowledge it. If absent, retry the original key after checking the attachment and versions again. If different, hold it for review. Never regenerate a key just because a reply timed out. Send comment edits on the same versioned batch route with the annotation key, expected object version and comment only. Check attachment identity and the current library checkpoint again. Freeze the sent draft during each request. Clear only that generation on acknowledgment and keep any newer local edits queued. (my call) [Zotero version rules](https://www.zotero.org/support/dev/web_api/v3/syncing) · [Versioned batch writes](https://www.zotero.org/support/dev/web_api/v3/write_requests) · [Server object version check](https://github.com/zotero/dataserver/blob/master/model/API.inc.php)
- On a version conflict (`412` or per-item mismatch), pull and compare the base, local draft and remote value. Retry against the new base when the attachment and annotation inputs are unchanged. If both changed the comment, show **Keep Zotero**, **Keep my comment** or **Copy my text to a project note…**. Ask before dropping the draft. If the parent was deleted or the file changed, keep the draft with **Copy my text…** and offer reselection only on a current file. Never recreate a removed parent. A revoked grant pauses the queue. A timed-out edit is settled by comparing the returned comment and version before retry. A permanent error leaves an entry with a reason and a way to copy the text. One failed write does not block unrelated entries. Advance the visible pull checkpoint only after a complete follow-up pull, since accepted writes can advance the server version. (my call) [Zotero conflict and version handling](https://www.zotero.org/support/dev/web_api/v3/syncing) · [Write responses](https://www.zotero.org/support/dev/web_api/v3/write_requests)
- **Quote to project note…** copies selected words or an annotation's quote into a new or selected Markdown note under `notes/`. **Insert quote and citation…** previews the quote and inserts escaped text plus `[@key, p. 194]` as one Undo step at the saved primary or secondary cursor. It can insert the citation alone. Both reuse the rc24 source snapshot and preview. Use the known printed label, with the file ordinal alongside for checking. If only the file ordinal is known, show it as a suggestion and ask for confirmation or a corrected printed page before inserting. Verify locator syntax, including Roman labels, through the rc24 parser. A standalone attachment without a parent needs an existing project source or a manually added one. If the target is stale or read-only, keep the quote in the preview and ask for a writable target. Show clearly that the quote is going to this project and may sync through its Drive settings. WrOS sends it to Zotero only as part of a separately saved annotation. (my call) [MLA locators](https://style.mla.org/in-text-citations-overview/) · [Zotero notes from annotations](https://www.zotero.org/support/pdf_reader) · [rc24 source and cursor rules](2026-11-21-rc24-essays-mla-zotero-design.md)

### Storage, recovery and network

- Keep the rc24 credential file and permissions. Keep the versioned SQLite database at `$XDG_DATA_HOME/grimoire/wros/zotero/<user-id>/library.sqlite3` (default `~/.local/share/grimoire/wros/zotero/<user-id>/library.sqlite3`). Store remote item JSON and versions, collections, tags, file fingerprints, project source links, pending edits and their bases. Use short transactions and a bounded WAL checkpoint policy. Write PDF bytes and per-page text boxes under `$XDG_CACHE_HOME/grimoire/zotero/<user-id>/` (default `~/.cache/grimoire/zotero/<user-id>/`). Make account directories private. Keep temporary files there. The queue lives with account data so clearing cache never removes unsent work. Names come from validated keys or hashes. (my call) [WrOS data path](../../../crates/grimoire-core/src/paths.rs) · [SQLite WAL](https://www.sqlite.org/wal.html)
- (my call) Start at 256 MiB total for the file and text cache, including pins, and a 64 MiB opening limit per PDF. Show space usage and keep a free-space reserve for the project and updates. Evict least recently read unpinned files first, protecting open files and files with pending edits. When everything is pinned or protected, offer to remove another download before starting. Profile one worker and a few pages in memory. Check 1,000 and 10,000 library objects, interrupted writes, suspend and low disk on the HP Stream. Use measured update and runtime cost to tune the defaults. [WrOS qualification](../../NIXOS_QUALIFICATION.md)
- (my call) Only accepted project snapshots, copied quotes, locators and project notes join the project, its Drive mirror, timeline and backup. A timeline restore changes project writing only. WrOS's account key, database, queue, PDF cache, downloaded bytes and temporary files stay outside projects, Drive and backups including settings. Restart and go-back preserve the account store. On disconnect stop jobs and clear credentials and cached copies. Record the identity of any in-flight send so reconnection can check its outcome. If there are drafts, offer **Cancel**, **Keep pending on this laptop**, or confirmed discard. Kept drafts remain private and can resume only after reconnection to the same account and file verification. Make that local retention visible. Offer a project-note copy before discard. Clear synced account rows and downloads while retaining the minimum text and identity needed for any kept draft. [Timeline](../../../crates/grimoire-core/src/timeline/mod.rs) · [Native backup](../../NATIVE_BACKUP.md)
- Add to `docs/API_AND_NETWORK_USE.md` at build time. **www.zotero.org and the Pages callback** get the rc24 pairing traffic when new access is requested. **api.zotero.org** gets the API key header, account ID, library version, requested item and collection keys and file requests. Sync receives item, collection, tag, attachment, annotation and deletion data. An explicitly requested download follows the API's signed storage redirect. Record the delivery hostname or exact verified host set from a live trace. Upstream uses signed Amazon S3 delivery and can use a Zotero proxy. The storage host gets the signed URL and returns file bytes without the library key. Annotation sends include only attachment and annotation keys, expected versions, position, page label, quote, color and comment. Local library search, PDF extraction and moving a quote into a project do not require network access. Keep job and error logs free of credentials, signed URLs and private text. No inbound port is needed.
