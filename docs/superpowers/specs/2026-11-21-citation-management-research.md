### Exchange formats

These are local text formats. Their specs and libraries have licences. The writer’s actual records can contain third-party data with separate rights. Each format works offline and needs no separate system package. Size scales with the records. For planning, 1,000 metadata-only entries at 1–3 KiB each take roughly 1–3 MiB before history or copies. That is a sizing assumption.

| Format | What it carries | Maintenance and fit |
| --- | --- | --- |
| BibTeX / BibLaTeX `.bib` | Citekeys and typed entries in a TeX-oriented text syntax. The two dialects differ in fields and types. LaTeX accents, brace-protected capitalization, string macros and cross-references need a real parser. | Widely supported by the checked tools. BibLaTeX has current CTAN documentation. Use for import, preserving stable keys, and consider export after mapping losses are known. [BibTeX format][bibtex] · [BibLaTeX project][biblatex] · [Pandoc input rules][pandoc-bib] · [Rust parser][rust-biblatex] |
| CSL-JSON | JSON array of items with `id`, `type`, structured names, dates and bibliographic fields. The CSL project publishes an input schema under its schema repo’s MIT licence. | Canonical project format. Keeps imports and CSL rendering on the same model. Supports machine validation and plain text diffs. [Schema repository][csl-schema] · [Item schema][csl-data] · [Hayagriva adapter][hay-json] |
| RIS | Tagged records, commonly beginning with `TY` and ending with `ER`. Field mappings and stable keys need checking across exporters. | Useful later for library and database handoff. Keep an import preview and show dropped fields. The current Pandoc guide and Zotero import docs list RIS. The historical specification’s maintenance status was unverified. [Pandoc input rules][pandoc-bib] · [Zotero import][zotero-import] |
| Hayagriva YAML | Keyed text entries with typed fields and parent works. | The maintained library’s own native format. A useful Typst interchange path. CSL-JSON has a more direct fit for Zotero handoff and the runner-up. [Format docs][hay-yaml] · [Library I/O][hay-io] |

## Recommended approach and runner-up

**Recommended.** Store plain CSL-JSON and use Hayagriva in `grimoire-core`. Build a small Grimoire form and a source picker. Reuse the existing BibLaTeX parsing library path for `.bib` and define a tested conversion into CSL-JSON. Preserve unknown fields that are valid CSL and warn when imported fields have no equivalent. Feed ordered citations, locales, actual note numbers and locators to the engine. Return styled text runs and bibliography entries to the current exporters. Keep the saved manuscript as Markdown. A narrow adapter allows WrOS to change processors without rewriting projects. [Hayagriva manifest][hay-manifest] · [CSL-JSON adapter][hay-json] · [Library I/O][hay-io] · [CSL specification][csl-spec]

**Runner-up.** Use a one-shot, local `pandoc --citeproc` helper with a Pandoc JSON document and read back its formatted inline, note, and bibliography nodes. Keep WrOS’s DOCX, EPUB and paperback renderers in charge of layout. Prove the adapter can recover source positions and note order and preserve style runs. Use the same local styles, metadata, and fixtures. This buys an independent implementation and supports the handoff Markdown directly. It costs a subprocess, larger update payload, and GPL distribution work. Use Pandoc off the appliance as a test oracle first. If neither on-device path passes, defer styled export and publish only the handoff once its imports and data safety are sound. [Pandoc citations][pandoc-cite] · [Pandoc release size][pandoc-assets] · [Haskell citeproc][cite-hs]

**Citation syntax.** Use a documented subset of Pandoc Markdown. Start with `[@ng2024]`, `[@ng2024, p. 12]`, and clusters such as `[@ng2024, pp. 12–14; @diaz2020]`. Use bracketed syntax even when typing by hand. Add narrative `@key`, suppressed author, prefixes, additional locator labels and explicit uncited inclusions only after their tests pass. Report unsupported citation forms that the parser can identify. Bare `@mentions` and email stay prose. Scan Markdown source ranges with `pulldown-cmark` context, preserving offsets through frontmatter removal, private `%%` notes and sample clipping. Skip code, escaped brackets, actual links and image syntax. Check Unicode, punctuation and caret offsets. Zettlr uses Pandoc-style keys. Obsidian workflows vary by plugin, with Citation Suite using Pandoc syntax. [Pandoc syntax][pandoc-syntax] · [Zettlr syntax][zettlr] · [Obsidian Citation Suite][obsidian]

`[^label]` continues to mean a scene-local public footnote. A bracketed citation can occur in its definition. Author-date citations there render inside the note. For Chicago, a citation inside a manual note renders as note text within that note. Body citations in Chicago create actual notes. Count manual and generated notes in reading order and pass that context to the processor for full and shortened references. A generated note does not create a new source definition. Test repeated labels, mixed note content, citation clusters and style punctuation explicitly. If the engine cannot give correct output for a supported case, show the scene and line in review and stop formatted export. [WrOS footnotes](../../../assets/help/05-notes-and-tks.md) · [CSL specification][csl-spec]

## Data, history, and recovery

- **Project.** `sources.json` at the root is the canonical UTF-8 CSL-JSON array. Keep one pretty-printed object per record, sorted by case-sensitive `id`, with consistent field order and a final newline. Human edits can be read and validated. Preserve any pre-existing file that fails validation. Preserve supported fields and intentional name order on write. Include common source types, names with literal or family/given forms, publication and access dates, DOI, ISBN and URL. Use an imported key if valid and unused. Suggest new keys from author and year, then fix them at first save. Show collisions and let the writer link duplicate records to an existing key. Preserve keys on ordinary edits. Defer cross-scene key rename and guard a delete if text still cites it. [CSL-JSON schema][csl-data]
- **Project style.** Use `[citations]` in `project.toml` for style ID, pinned revision, and locale. Ship a small versioned set of independent style XML files and matching locales in the signed build. Preserve the exact pinned selection or offer an explicit migration with a preview before changing it. Use the rc22 resolver for old folders. Treat missing configuration as disabled until a style is chosen. Existing projects need no conversion. [rc22 design](2026-11-21-rc22-projects-youtube-keys-design.md) · [CSL styles][styles] · [CSL locales][locales]
- **Writer.** Per-user configuration may remember the last import folder, a default style for new projects, and the online lookup toggle. A disposable, bounded identifier cache can live under the writer’s cache directory. Accepted records live in the project. Defer any personal library until there is demand. A future library should copy a record into each project when it is cited so an archived project can stand on its own. No account secrets, library caches, PDFs or browser snapshots in `sources.json`.
- **Writes and sync.** Reuse the atomic writer and expected-content checks. Revalidate the original fingerprint at save and import and coordinate those writes with an in-flight WrOS sync. On a stale editor, preserve the proposed edit until the writer can settle it. The helper syncs ordinary visible files by hash, including `.json`. Its merge-base text allowlist excludes `.json`, and the desk conflict view is tied to Markdown nodes. Teach `wros-sync` to snapshot the reserved root `sources.json` as text under the existing size bound. Use its parked copy and pending record in the desk. Compare base/local/Drive by ID. Disjoint record changes can merge after validation. Concurrent edits to a record, ambiguous key collisions and delete-versus-edit require a choice. Resolve through the existing pending-file contract only after verifying the selected inputs. Keep copies on failed validation. The helper can also sync visible `exports/` files, so the Markdown handoff should include only cited records and avoid private fields. [Sync helper](../../../os/scripts/wros-sync) · [Backup and sync UI](../../../src/app/backup.rs) · [Conflict overlay](../../../src/app/overlays/conflicts.rs)
- **Timeline and backup.** Invoke the same save/checkpoint notification used for project edits. Git stages permitted files, so a root sidecar produces small line diffs and travels in the timeline bundle. Add a sources restore entry or a clear way to select the historical sidecar without reverting unrelated scenes. Encrypted backup stages the whole project. Folder import and backup restore should carry and validate the sidecar, while retaining the original byte content on validation errors. A portable handoff beside a Markdown export carries its own references. Compiled reader outputs carry formatted text. A plain DOCX or EPUB cannot reconstruct the original keys and complete records by itself. ## Export behaviour

Run citation processing on the exact selected stream for each edition, including its front and back matter. Exclude private notes, excluded scenes, and prose outside the sample. Resolve a sample boundary before it can split a marker. Compute bibliography order, disambiguation, shortening and note numbering separately for each edition. Preserve style emphasis, punctuation, superscripts and hanging indents through typed runs. Treat item text and processor output as data and escape it for the target renderer. Check requested formats before publishing companion files for citation or note errors. The checkout already validates Word and EPUB early, while paperback rendering occurs later. Move paperback citation and note validation ahead of writes. A later LibreOffice failure can still leave its useful Word companion with an explicit PDF error. [Core export](../../../crates/grimoire-core/src/export.rs) · [Paperback exporter](../../../crates/grimoire-core/src/export_print.rs)

Enable lookups explicitly under **Settings › Writing › Citations › Online source lookup**. When the writer presses **Look up**, send only the normalized identifier and required protocol data to the named service. Provider identification should use a project-operated support contact where appropriate, with no use of the writer’s author email. Use one request at a time, a short timeout and a bounded response. Respect retries and provider backoff, keep the UI responsive, and cache by provider and identifier. No fallback to another provider after timeout or throttling. A definitive Crossref no-match can offer the DataCite fallback. Skip background refresh, manuscript search and attachment retrieval. Update the [WrOS network audit](../../API_AND_NETWORK_USE.md) with exact hosts, triggers and data sent.

Google Drive uses WrOS’s existing phone-assisted authorization, plus documented masked input and USB options. File import or these public identifier APIs need no Zotero account. Zotero’s Web API documents manually made keys and OAuth 1.0a key exchange. A browserless device-code flow was not found in those docs. If a private-library import ever becomes necessary, the writer could use a browser on a phone or another computer to make a least-privilege read-only key, then enter it through a private WrOS form. Keep it outside projects, logs, arguments and sync state. Read a selected collection with version and pagination handling, obey `Backoff`, `429` and `Retry-After`, and offer revoke instructions. No Zotero credentials or callback service is needed for the proposed releases. Do not forward the local Zotero port. ## Risks and unconfirmed points

- **Citation correctness is the largest engineering risk.** Hayagriva’s CSL-JSON adapter has a field-by-field implementation. A record that validates against the schema can still expose rendering gaps. Upstream issue #500 shows a first-reference note-number failure in Typst and gaps in the library’s test coverage. Its follow-up suggests the caller’s note-number input matters. Test that behavior when WrOS supplies actual numbers. Also test archival items, missing dates, non-Latin names, title casing, and style-specific bibliography markup. Qualify specialized legal citations before offering them. [CSL-JSON adapter][hay-json] · [Upstream note-number issue][hay-notes-issue] · [CSL specification][csl-spec]
- **Scope affects results.** Sampling, edition matter, numbered notes, and the position of a bibliography can all change citation output. Use actual rendered order for each edition. Include empty bibliography, arrays with duplicate IDs, and stale scene/style data in the test set. Include a golden case where the bibliography and `END` or other closing content must both be placed correctly.
- **Record identity and import loss.** A Zotero item key, a generated `.bib` citekey, and a DOI serve different purposes. Preview keys and preserve them on import. An ISBN identifies an edition, while a preprint and published article may warrant separate records. Compare full titles and contributors before replacing edited metadata. Reading a file exported by Zotero does not migrate its collections, attachments or annotations. [Zotero export][zotero-export] · [Better BibTeX export][bbt-docs] · [Open Library Books API][ol-books]
- **Sync can pair different revisions of a scene and its sources.** The current helper works file by file. Detect unresolved keys after a partial sync and give the writer a source conflict route. Neither import nor export should silently take the last-arriving bibliography. Test actual Drive behavior and restoration, including interrupted transfers. [Sync helper](../../../os/scripts/wros-sync)
- **Verification gaps.** No candidate was built or run here. Engine parity, dependency/closure deltas and real-device accessibility remain unmeasured. Search pages and some exact-pin package files were inaccessible. Unconfirmed package entries and missing download sizes are marked in the tables. Codeberg access prevented a direct bibiman release-history check. Provider policies can change and need rechecking before integration ships. The full #163 thread remains unavailable in this checkout.
