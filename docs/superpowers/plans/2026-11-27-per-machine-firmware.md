# Per-machine firmware Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each installed WrOS loads all of its firmware from a per-machine set, picked from its own hardware, kept per system generation, delivered signed in updates. The signed system stays identical for every laptop.

**Architecture:** Driver packages are built as in rc32, plus a table (package → modules, store path, NAR hash) that the system carries without referencing the packages. A root tool, `wros-firmware`, detects the packages a laptop needs and writes a symlink folder per system generation. Activation points `/lib/firmware` at it. GRUB's per-generation `append-initrd-secrets` hook packs the early-boot part into a second initrd. The update engine fetches only the needed packages from a new, signed `firmware` section of the closure manifest.

**Tech Stack:** Nix/NixOS modules, Python 3 stdlib (engine and tool, as now), Rust (Settings row in wros-sys and the app), NixOS VM tests.

**Spec:** `docs/superpowers/specs/2026-11-27-per-machine-firmware-design.md` (approved 2026-11-27). Read it first: this plan argues from it.

## Global Constraints

- The system toplevel is the same for every laptop. Nothing per-machine goes into the system closure, and nothing is compiled on the laptop.
- The system closure must **not** reference the driver packages, except the seed (Stream) packages: rtw88, i915-glk, sof.
- Every cache file the update site hosts stays under 95 MB (GitHub Pages refuses ≥100 MB). The whole site stays under 1 GB.
- The live ISO carries every driver package, and the same store paths the installed system's table names.
- Code that runs as root (`wros-firmware`, the engine, the installer) writes only under `/nix/var/wros/firmware`, `/nix/var/nix/gcroots/wros-firmware`, `/lib/firmware` (one symlink) and the bootloader's initrd-secrets file. It refuses symlinks planted in those places (lstat, `O_NOFOLLOW`, owner root, not group or world writable), as the engine already does.
- A detection that finds nothing, or fails, never removes a package from a set: the new set is the union of what's detected and what the current generation's set already has.
- Python: stdlib only. Rust: no new crates.
- The help and the docs follow CLAUDE.md: a Settings row is named in `23-settings.md`, `27-the-menu.md` (if it's a menu row) and `28-wros.md`.
- Paths and names (used by every task):
  - tool: `nixos/scripts/wros-firmware` (Python), installed as `/run/current-system/sw/bin/wros-firmware`;
  - table: `${toplevel}/wros-firmware.json` (via `system.systemBuilderCommands`);
  - sets: `/nix/var/wros/firmware/<toplevel store name>/lib/firmware/…`;
  - GC roots: `/nix/var/nix/gcroots/wros-firmware/<toplevel store name>--<package>`;
  - early-boot folder in the initrd: `/wros-firmware/…`, found through the kernel parameter `firmware_class.path=/wros-firmware` (stage 2's activation then sets NixOS's own path, as now).

## Review Focus

1. **rc32 → rc33 with the old engine.** The old engine knows nothing of sets. The seed packages and `wros-firmware ensure`, run from the bootloader hook and from activation, must leave the Stream with Wi-Fi, display and sound on the first boot of rc33.
2. **Go back.** After rc33 → rc34, booting the previous generation uses its own folder. Pruning removes folders only for generations that no longer exist.
3. **Detection gaps.** Unknown aliases, `modprobe` failing, or a package missing from the store. Never an emptier set (union rule); report what's missing.
4. **Planted paths.** A symlink at `/lib/firmware`, in the sets folder or the GC roots folder.
5. **`/boot` space.** The ESP is 512 MiB, FAT32. The early-boot cpio holds only initrd drivers' firmware (graphics). Refuse to write it, with a clear message, when the ESP would drop below 64 MiB free.

### Task 1: Driver packages, the table and the seed

**Files:**

**Interfaces:**
- Produces: `config.wros.firmware.<name>` for every package, including `sof`. `config.system.build.wrosFirmwareTable` is a JSON file of this shape:

  ```json
  {"format": 1, "packages": {"<name>": {"store_path": "/nix/store/…", "nar_sha256": "<hex>",
    "nar_size": 123, "modules": ["rtw88_8822be", "…"], "initrd": false}}}
  ```

  It's installed at `${toplevel}/wros-firmware.json`.

- [ ] **Step 1:** Add the drivers to `drivers` in firmware.nix:
  - amdgpu `gpu/drm/amd/**/*.ko*`;
  - radeon `gpu/drm/radeon/**/*.ko*`;
  - xe `gpu/drm/xe/**/*.ko*`;
  - bt-intel `bluetooth/btintel.ko*` + `bluetooth/btusb.ko*`, fallback `intel/ibt-*`;
  - bt-realtek `bluetooth/btrtl.ko*`, fallback `rtl_bt`;
  - bt-qca `bluetooth/btqca.ko*`, fallback `qca`;
  - bt-broadcom `bluetooth/btbcm.ko*`, fallback `brcm/BCM*`.

  Add `sof`: a package wrapping `pkgs.sof-firmware`'s `lib/firmware` (compressed as the others are), with modules `sound/soc/sof/**/*.ko*`. Regenerate the lists with `system.build.wrosFirmwareLists` and commit them. Keep `wrosFirmwareListsCurrent` passing.
- [ ] **Step 2:** Build the table in two derivations, so the system doesn't reference the packages:
  - (a) `wros-firmware-hashes`: takes the packages as inputs and writes `{name: {nar_sha256, nar_size}}` using `nix-store --dump` piped to sha256. Names only, no paths.
  - (b) `wros-firmware-table`: takes (a) and a JSON string of `name → store path` built with `builtins.unsafeDiscardStringContext`, plus module names (from the lists step, also context-free), and merges them.

  `initrd` is true for packages whose modules include any in `boot.initrd.kernelModules` or `availableKernelModules`. i915 is already there. Add amdgpu, radeon and xe to `availableKernelModules`, not `kernelModules`: udev loads them in stage 1 only where the hardware is, and the main initrd grows only by the modules.
- [ ] **Step 3:** Wiring:
  - **installed.nix** keeps the Stream seed (`rtw88`, `i915-glk`, `sof`) in `hardware.firmware` so the kernel can still find it if linking the per-machine set fails.
  - **hardware.nix** supplies only regdb. The installed and live systems add their own firmware packages.
  - **installed:** `system.extraDependencies = [ rtw88 i915-glk sof ]` (the seed). Install the table with `system.systemBuilderCommands`.
  - **live.nix:** `hardware.firmware` = every package (including sof). The `availableKernelModules` change in hardware.nix applies to both systems.
  - Keep the Stream assertions.
- [ ] **Step 4:** The `firmware-table` check. Evaluate the installed system and assert:
  - the table lists every package with a valid store path and 64-hex hash;
  - `nix-store -qR` of the toplevel contains no driver package except the three seeds;
  - the live ISO closure contains every table store path;
  - every package's compressed NAR (from `nix-store --dump | zstd -19`) is < 95 MB.

  Run: `CHECK=firmware-table rc33-work/vm.sh firmware-table`. Expected: PASS.
- [ ] **Step 5:** Run `check.sh all` and `check.sh py`. Report the size of each package.

### Task 2: `wros-firmware`, the root tool

**Files:**
- Create: `nixos/scripts/wros-firmware` (Python 3, stdlib), packaged in `nixos/pkgs/helpers.nix` next to the engine
- Test: `os/tests/test_wros_firmware.py`

**Interfaces:**
- Consumes: the table format from Task 1.
- Produces (subcommands; every one prints one JSON line on success and exits non-zero with a plain message on failure):
  - `detect --system <toplevel> [--sys-root /] [--modules <dir>]` → `{"packages": [...], "unknown": [...]}`. It reads every `<sys-root>/sys/bus/*/devices/*/modalias`, resolves each with `modprobe -d <modules root> -S <kernel version> --resolve-alias`, adds `<sys-root>/proc/modules`' names, and maps module names to packages through the table. The kernel version and modules root come from `<toplevel>/kernel-modules/lib/modules/*`.
  - **Packages that share a module** (`i915` and the Stream's trimmed `i915-glk` both map from
    `i915`): a module picks exactly one of them. Prefer one already in the running set; else
    the largest (by `nar_size`) present in the store; else the largest. So the Stream keeps
    i915-glk (its seed), and a new Intel laptop installed from the ISO gets the full i915. Test:
    `test_a_module_two_packages_share_picks_one`.
  - `ensure <toplevel> [--add NAME…]` writes the folder and GC roots for that generation. It unions the detected names, `--add`, and the names in the running and target generations' `packages.json` files. It uses packages present in the store and reports `missing`. It builds a `.new-<generation>` folder and swaps it with the existing folder using `renameat2(RENAME_EXCHANGE)`. It uses plain rename when there is no existing folder. It never leaves an emptier set.
  - `initrd <toplevel> <out-file>` writes an uncompressed `newc` cpio of that generation's folder, for `initrd: true` packages only, at `wros-firmware/<file>` with symlinks resolved. It refuses if the file's filesystem would drop below 64 MiB free. With no folder, it runs `ensure` first.
  - `link <toplevel>` points `/lib/firmware` at that generation's folder (creating `/lib` if missing; replacing only a symlink it owns; refusing a real directory). With no folder, it runs `ensure` first.
  - `prune --profile /nix/var/nix/profiles/system` keeps folders and roots for the numbered profile generations, the systems named by `/run/current-system` and `/run/booted-system`, and the set currently linked at `/lib/firmware`. It removes the rest.
  - `--root <dir>` (tests only) prefixes every absolute path it writes; `TRUSTED_UID` as in the engine.

- [ ] **Step 1: Write the failing tests** with fake trees: a sys tree with three modalias files, a fake `modules.alias` (run the real `modprobe -d` against a tiny modules dir with `modules.alias` and `modules.dep` only), a table, and fake store packages:
  - `test_detect_maps_aliases_and_loaded_modules_to_packages`;
  - `test_an_unknown_alias_is_reported_not_fatal`;
  - `test_ensure_keeps_the_running_sets_packages` (union rule);
  - `test_ensure_reports_a_package_missing_from_the_store`;
  - `test_ensure_refuses_a_planted_symlink`;
  - `test_initrd_packs_only_early_boot_firmware` (read back the cpio with Python);
  - `test_initrd_refuses_when_boot_is_almost_full`;
  - `test_link_replaces_its_own_symlink_and_refuses_a_directory`;
  - `test_prune_keeps_folders_of_existing_generations`.
- [ ] **Step 2:** Run them (`check.sh py`). Expected: FAIL (no tool yet).
- [ ] **Step 3:** Implement. No shell=True; argv lists only.
- [ ] **Step 4:** Run `check.sh py`. Expected: all pass.

**Interfaces:**
- Produces: in `closure-manifest.json`, a `firmware` object:

  ```json
  {"<name>": {"store_path": "/nix/store/…", "files": [<cache file entries, the same shape as cache_files>]}}
  ```

  These files are hosted in the same `cache/`, are never pruned by the baseline delta, and are never thinned (they aren't on cache.nixos.org). `parse_closure_manifest` validates it: names `[a-z0-9-]{1,40}`, at most 64 packages, valid store paths, entry rules as in `cache_files`, no file path also in `cache_files` or in another package. ### Task 8: *Firmware for a new device* from a WrOS USB stick (offline)

**Files:** as Task 7, plus the engine's existing update-media mount (`find_update_media`).

**Interfaces:**
- When the channel can't be reached, the verb looks for a mounted WrOS stick (`find_update_media`) and its Nix store (the live ISO's squashfs). It takes a package from the stick only if:
  - its store path equals the running system's table entry;
  - after `nix-store --dump`, its NAR SHA-256 and size equal the table's `nar_sha256`/`nar_size`.

  The running system is signed and verified, so the table is the trust anchor. It imports with `nix-store --import` from a `nix-store --export` stream built from the dump, or another way that keeps the store path and records the hash. Then it runs `ensure` and boot, as Task 7.
