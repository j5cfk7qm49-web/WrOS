## NixOS verification

Use the candidate's `flake.lock` for release evidence. The legacy `nctest.sh` and `n3.sh`
helpers copy a separate lock into their Linux staging folder. Check that pin first or use
a Linux copy of the candidate with its own lock. `n3.sh` formats the source worktree and
filters output. Check individual command exit statuses for qualification.

From the candidate checkout in a NixOS dev shell:

~~~sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test -p grimoire-brain --locked
cargo test -p grimoire-tui --locked
cargo test --no-default-features --features test-driver,pty-qa --test driven --locked
nix build -L .#checks.x86_64-linux.brain-backup
~~~

The stage 0 binary should accept `--seed`, `--profile` and `--output`. Run release-mode
`brain-bench --seed 25001 --profile aged --output rc25-brain-bench.json` on the HP Stream
with the agreed workload and limits. Retain the complete JSON with the stage 0 decision.
