# rc32: Upstream Grimoire 0.8–0.9, Then Cleanup: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge upstream GrimoireTUI v0.8.3 and then v0.9.1 into WrOS, with every intentional difference written down. Then clean the code up (hygiene everywhere; restructure only WrOS-owned code), and ship it as rc32.

**Architecture:**
- Two real `git merge`s, so the merge base moves, resolved by the rules below.
- One-concern commits for the cleanup, each green on the full Rust/Python/gate checks.
- The VM tests and the release go through `rc14-argon/nixos-wsl/qualify.sh` at the end.

**Tech Stack:** Rust 2024 (workspace, ratatui 0.30), Nix flake checks, NixOS-WSL for builds,
Codex (`gpt-6.2-sol`) for the bulk edits in its own worktree. The reviewer compiles, tests and
commits.

**Spec:** `docs/superpowers/specs/2026-11-27-upstream-and-cleanup-design.md`

## Global Constraints

- **Ownership.** A file is *shared* if it exists in `git ls-tree -r <latest upstream tag merged>`
  (v0.8.3 after Task 1, v0.9.1 after Task 3). All other files, and the `wros-*` crates, are
  *WrOS-owned*.
  - In shared files: bug fixes and local hygiene only, no restructuring, no renames.
  - WrOS code inside shared files (the `App` fields in `src/app.rs`, WrOS lines in
    `src/music/mod.rs` and `setup.rs`) is not moved.
- **Projects on disk are untouched:** `project.toml` / `novel.toml`, `~/Documents/Grimoire`, and
  the rc22 migration (`grimoire_core::project_files`, `src/app/project_names.rs`).
- **Words:** in user-visible WrOS text a book is a "project" (rc22 sweep). Upstream text that is
  taken follows that rule.
- **The help rule (upstream CLAUDE.md):** every change a writer can see updates `assets/help/` in
  the same commit; the help tests must pass.
- **No behaviour change** in the cleanup tasks. The screen tests pass unchanged; a test changes
  only if it read private internals that moved.
- **Untouched:** locking, sleep, restart, shut down, the installer, and code that runs as root or
  as `wros-keys`. Only lint-level edits are allowed there, and only where a task names them.
- **Toolchain:** no new crates, except where a merged upstream change brings one; no toolchain or
  nixpkgs bump.
- **Formatting:** rustfmt with 100 columns; clippy `-D warnings`.
- **Every task ends green:**
  - `rc32-work/all.sh`: fmt, clippy on all targets, all Rust tests;
  - `rc32-work/py.sh`: the python-suite;
  - `rc32-work/gates.sh`: nix-gates.
  - Each runs from Windows as `MSYS_NO_PATHCONV=1 wsl -d NixOS -- bash /mnt/c/Users/lettuce/Documents/ChatGPT/WrOS/rc32-work/<script>`
    with `SRC` defaulting to `WrOS/rc32-codex`.

## Review Focus

1. **Upstream code that finds a book by `novel.toml`** must also accept WrOS's `project.toml`.
   This covers `is_book`, open a copy, move home, `books_in`, and the "Where kept" facts. Test:
   a `.zip` copy of a project with `project.toml` opens as a project.
2. **New upstream keys inside WrOS screens.** `c`, `f`, `d`, `u`, `o`, `m`, `-`/`+`, right-click
   and menu clicks must not shadow WrOS keys in the same pane. WrOS's Esc menu, the bars and the
   tiles keep their behaviour. Test: the existing `menu_map_ui_tests` and `bar_ui_tests` pass, and
   the help's every-key test lists any new key once.
3. **Paste never runs as keys**, in WrOS's own overlays too (Settings, sources, pins). Test: a
   paste into the WrOS Settings list changes nothing but a text field.
4. **Save a copy and open a copy** write only inside `~/Documents/Grimoire/Copies` and
   `~/Documents/Grimoire`, and never replace an existing folder or copy. Test: two saves the same
   day give two files; opening a copy whose name exists picks a free name.
5. **Removing the Debian channel** leaves the NixOS channel deploy working. Test: the workflow
   test in the python-suite still asserts the `nixos-updates/` and `pages/` steps, and the
   rc32 release deploy succeeds.
