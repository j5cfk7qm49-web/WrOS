# rc30 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship rc30 with these changes:
- the new chrome: W r O S tiles, the ⏻ tile, Platinum menus, two bottom bars and widget popups
- the view renames (Write, read, Outline, Study; the notes folder becomes Commonplace)
- fixes for #175 and #174
- a smaller and sturdier update channel
- a PDF/OCR measurement kit for the HP Stream

**Architecture:**
- **The chrome** reuses ratatui drawing that already exists: `ui.rs` for the layout and status, `overlays/bar.rs` for the menus, and `wros-graphics` glyphs for the tiles. Every popup reuses a `wros_sys::Request` that Settings already sends. No popup adds a privileged helper.
- **The fixes and the channel work** happen in NixOS-WSL, where they're verified by VM tests and a trial bundle.

**Tech Stack:** Rust (ratatui, crossterm), NixOS modules and VM tests, Python helpers, Codex `exec` (Sol = `gpt-6.2-sol`, Terra = `gpt-6.1-terra`).

**Spec:** `docs/superpowers/specs/2026-11-25-rc30-interface-layout-design.md`. The Brain design's answers are `2026-11-22-brain-library-review-design.md`.

## Global Constraints

- **Codex can't compile or run tests** (its sandbox blocks `wsl`). I run fmt, `clippy -D warnings`, the grimoire-tui and core tests, nix-gates and the python-suite for every Codex commit before folding it in.
- **Codex runs one task at a time**, in `WrOS/rc30-codex` on branch `rc30-codex`. Each task is committed as `wip(codex): rc30 task N (unreviewed)`. I review it and cherry-pick it into `rc30`.
- **Never give Codex** the lock chain, the sleep or power paths, or anything else that runs as root or as `wros-keys`, without a line-by-line review from me. Terra never gets those at all.
- **Colours come only from the theme's roles** (accent, text, dim, border, sel, warn, band) and change live with the theme. Rainbow paints accent cells in its spectrum. The plain console (`app.linux_console`) uses ASCII and 16-colour fallbacks.
- **Info-section rule (the owner's):** it never shows anything already easy to read somewhere else on screen.
- **Popups** reuse the requests Settings already uses: `Request::Wifi`, the Wi-Fi network routes, `Request::SetVolume`, `Request::Brightness` and the warm-screen routes. **Cut line:** anything that needs a new privileged helper moves to rc31. The night light toggle opens the existing warm-screen preview (Keep/Cancel); an instant toggle is #173.
- **One VM test at a time** in NixOS-WSL, with nothing else heavy running.
- **The online bundle is thin from rc29**, which the laptop runs. Every file must stay under the 99M gate.
- **Owner screenshots gate publishing.** Before publishing, render the real screens and send them: four themes plus the console, the popups and focus mode.

## Review Focus

1. **An 80-column console with every mark showing:** the tiles, menus, marks and ⏻ must all fit. Titles drop from the right before the ⏻ tile does, and the save warning ● is never dropped. The test goes in Task 3.
2. **Mouse clicks after the layout change:** the tree, editor, scene list and menu rows are now one row lower (bottom) and unchanged (top). The click-coordinate tests have to cover the new bottom bars. Tests go in Tasks 3 and 5.
3. **The live session:** the ⏻ menu shows Install to disk and a dim Lock. The VM test `live-session.nix` must reach it from the keyboard. The test goes in Task 3, with the VM edit by me.
4. **Focus mode with a failed save:** the single bottom line still shows ● and ⚠. The test goes in Task 5.
5. **A very long project › chapter › scene path at 40 columns:** it's shortened from the left, and the scene name stays whole. The test goes in Task 5.

## Phase B: chrome

### Task 2 (Terra): tile glyphs

**Files:**
- `crates/wros-graphics/build.rs` (generated tile cells)
- `assets/fonts/wros-narrow.txt` (the hand-drawn ⏻ and the dot)
- test in `crates/wros-graphics/src/unifont.rs`

**Produces:** these private-use code points, all one cell wide, in `glyph()`:

| Code point | What it is |
|---|---|
| `U+E100` | tile left edge: column 6 on rows 1–14, plus rows 1 and 14 on columns 6–7 |
| `U+E101` | tile right edge: column 1 on rows 1–14, plus rows 1 and 14 on columns 0–1 |
| `U+E102` | tile right edge with the due dot: like E101, plus pixels (3,3), (4,3), (3,4) and (4,4) |
| `U+E110` to `U+E113` | Unifont's W, r, O and S with rows 1 and 14 set across the cell, generated in build.rs |
| `U+E114` | ⏻ drawn in one cell, with rows 1 and 14 set (in wros-narrow.txt) |

So a tile is three cells: `E100 E11x E101`.

- [ ] **Step 1:** test `tile_cells_have_their_frame`:
  - For each of E110–E114, rows 1 and 14 are fully set.
  - E100 has column 6 set on rows 1–14.
  - E101 has column 1 set on rows 1–14.
  - E102 equals E101 plus the 4 dot pixels.
- [ ] **Step 2:** generate E110–E113 in build.rs from Unifont's own letters, OR-ing in rows 1 and 14. Draw E100, E101, E102 and E114 in wros-narrow.txt, following the file's format.
- [ ] **Step 3 (me):** `cargo test -p wros-graphics`, expected to pass.
- [ ] **Step 4:** commit.
